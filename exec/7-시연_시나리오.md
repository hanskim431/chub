# 7. 시연 시나리오

본 문서는 CHUB Interview Platform의 주요 기능을 시연하기 위한 단계별 가이드입니다.

---

## 시연 준비

### 사전 준비사항
- [ ] 백엔드 서버 실행 확인 (`http://localhost:8080` 또는 `https://chub.ai.kr`)
- [ ] 프론트엔드 서버 실행 확인 (`http://localhost:3000` 또는 `https://chub.ai.kr`)
- [ ] PostgreSQL 데이터베이스 연결 확인
- [ ] MongoDB 데이터베이스 연결 확인
- [ ] 카카오 로그인 계정 2개 준비 (피면접자용, 면접관용)
- [ ] 테스트용 PDF 이력서 파일 준비 (10MB 이하)
- [ ] 브라우저 2개 또는 시크릿 모드 준비 (동시 접속 테스트용)

### 테스트 계정
- **피면접자 계정**: 카카오 계정 A
- **면접관 계정**: 카카오 계정 B

---

## 시나리오 1: 회원가입 및 로그인 (카카오 OAuth)

### 목표
카카오 소셜 로그인을 통한 회원가입 및 로그인 기능 시연

### 단계

#### 1-1. 메인 페이지 접속
1. **URL**: `https://chub.ai.kr` 접속
2. **화면**: 랜딩 페이지 또는 로그인 버튼 확인
3. **클릭**: "카카오로 시작하기" 또는 "로그인" 버튼 클릭

#### 1-2. 카카오 로그인
1. **화면**: 카카오 로그인 페이지로 리다이렉트
2. **입력**: 카카오 계정 A (피면접자용) 이메일/비밀번호 입력
3. **클릭**: "로그인" 버튼 클릭
4. **동의**: 권한 동의 화면에서 "동의하고 계속하기" 클릭

#### 1-3. 리다이렉트 및 토큰 발급
1. **자동**: 백엔드로 Authorization Code 전송
2. **자동**: JWT Access/Refresh Token 발급
3. **자동**: 쿠키에 토큰 저장
4. **화면**: 메인 대시보드 또는 프로필 설정 페이지로 이동

#### 1-4. 로그인 확인
1. **확인**: 우측 상단에 프로필 이미지/이름 표시
2. **확인**: 개발자 도구 > Application > Cookies 에서 토큰 확인

**예상 결과:**
- 카카오 프로필 정보가 자동으로 입력됨
- 사용자가 데이터베이스에 생성됨 (users 테이블)

## 시나리오 2: 면접관 프로필 생성

### 목표
면접관으로서 상세 프로필 등록 기능 시연

### 단계

#### 2-1. 면접관 프로필 페이지 이동
1. **클릭**: 네비게이션 바에서 "면접관 등록" 또는 "프로필 설정" 클릭
2. **화면**: 면접관 프로필 입력 폼 표시

#### 2-2. 기본 정보 입력
1. **입력**: 회사명 (예: "Samsung Electronics")
2. **입력**: 직책 (예: "Senior Software Engineer")
3. **입력**: 부서 (예: "Platform Development")
4. **선택**: 경력 레벨 (예: "SENIOR")
5. **입력**: 총 경력 연수 (예: 10년)
6. **입력**: 소개 (예: "10년간 백엔드 개발 경험이 있습니다.")

#### 2-3. 전문 분야 입력
1. **클릭**: "전문 분야 추가" 버튼
2. **입력**:
   - 전문 분야: "Backend Development"
   - 설명: "Spring Boot, JPA, Microservices"
3. **클릭**: "추가" 버튼
4. **반복**: 여러 전문 분야 추가

#### 2-4. 경력 사항 입력
1. **클릭**: "경력 추가" 버튼
2. **입력**:
   - 회사명: "Samsung Electronics"
   - 직책: "Senior Software Engineer"
   - 시작일: "2014-03-01"
   - 종료일: (현재 재직 중인 경우 비워둠)
   - 설명: "Platform backend development"
3. **클릭**: "추가" 버튼

#### 2-5. 학력 입력
1. **클릭**: "학력 추가" 버튼
2. **입력**:
   - 학교명: "Seoul National University"
   - 학위: "Bachelor"
   - 전공: "Computer Science"
   - 입학일: "2010-03-01"
   - 졸업일: "2014-02-28"
3. **클릭**: "추가" 버튼

#### 2-6. 가능 시간대 설정
1. **클릭**: "시간대 추가" 버튼
2. **선택**: 요일 (예: "MONDAY")
3. **입력**: 시작 시간 (예: "09:00")
4. **입력**: 종료 시간 (예: "12:00")
5. **클릭**: "추가" 버튼
6. **반복**: 여러 시간대 추가

#### 2-7. 면접 정보 입력
1. **입력**: 분야 (예: "Backend")
2. **입력**: 면접 가격 (예: 50,000원)
3. **입력**: 면접 스타일 (예: "실무 중심의 기술 면접을 진행합니다.")

#### 2-8. 프로필 저장
1. **클릭**: "프로필 저장" 버튼
2. **확인**: 성공 메시지 표시 ("프로필이 저장되었습니다.")
3. **자동**: 면접관 목록 페이지로 이동

**예상 결과:**
- 면접관 프로필이 데이터베이스에 저장됨 (interviewer_profiles 테이블)
- JSONB 형식으로 복잡한 데이터 구조 저장 확인

## 시나리오 3: 이력서 업로드

### 목표
PDF 이력서 파일 업로드 기능 시연

### 단계

#### 3-1. 이력서 페이지 이동
1. **클릭**: 네비게이션 바에서 "이력서" 또는 "마이페이지" 클릭
2. **화면**: 이력서 업로드 화면 표시

#### 3-2. 파일 선택
1. **클릭**: "파일 선택" 또는 "이력서 업로드" 버튼
2. **선택**: 준비한 PDF 이력서 파일 선택 (10MB 이하)
3. **확인**: 파일명 및 크기 표시

#### 3-3. 파일 업로드
1. **클릭**: "업로드" 버튼
2. **대기**: 업로드 진행 상태 표시 (프로그레스 바)
3. **확인**: 업로드 완료 메시지 표시

#### 3-4. 업로드된 파일 확인
1. **확인**: 업로드된 이력서 목록에 표시
2. **클릭**: "미리보기" 버튼 (선택사항)
3. **화면**: PDF 뷰어로 이력서 내용 확인

#### 3-5. 파일 URL 확인 (개발자 도구)
1. **열기**: 개발자 도구 > Network 탭
2. **확인**: PDF 파일 요청 URL 확인
   - 예시: `https://chub.ai.kr/files/resumes/1234567890_resume.pdf`

**예상 결과:**
- 파일이 `/app/uploads/resumes/` 디렉토리에 저장됨
- 파일 URL이 데이터베이스에 저장됨 (resumes 테이블)
- NGINX를 통해 파일 접근 가능

## 시나리오 4: 면접관 검색 및 프로필 조회

### 목표
면접관 목록 조회 및 상세 프로필 확인 기능 시연

### 단계

#### 4-1. 면접관 목록 페이지 이동
1. **클릭**: 네비게이션 바에서 "면접관 찾기" 또는 "Browse Interviewers" 클릭
2. **화면**: 면접관 목록 카드 형태로 표시

#### 4-2. 필터링 (선택사항)
1. **선택**: 분야 필터 (예: "Backend")
2. **슬라이더**: 가격 범위 설정 (예: 0원 ~ 100,000원)
3. **확인**: 필터링된 면접관 목록 표시

#### 4-3. 면접관 프로필 상세 조회
1. **클릭**: 면접관 카드에서 "프로필 보기" 버튼 클릭
2. **화면**: 면접관 상세 프로필 페이지로 이동
3. **확인**:
   - 기본 정보 (이름, 회사, 직책, 경력)
   - 전문 분야 목록
   - 경력 사항
   - 학력 사항
   - 가능 시간대
   - 면접 가격 및 스타일

#### 4-4. 면접 요청 버튼 확인
1. **확인**: "면접 요청하기" 버튼 표시
2. **준비**: 다음 시나리오를 위해 버튼 위치 확인

**예상 결과:**
- 면접관 목록이 정상적으로 조회됨
- JSONB 데이터가 정상적으로 파싱되어 표시됨

## 시나리오 5: 면접 요청 및 승인

### 목표
피면접자가 면접을 요청하고 면접관이 승인하는 전체 플로우 시연

### 단계 (피면접자)

#### 5-1. 면접 요청하기
1. **위치**: 면접관 상세 프로필 페이지
2. **클릭**: "면접 요청하기" 버튼
3. **화면**: 면접 요청 모달 또는 폼 표시

#### 5-2. 요청 정보 입력
1. **입력**: 요청 메시지 (예: "백엔드 개발자 포지션 모의 면접을 요청드립니다.")
2. **선택**: 희망 날짜 (달력 UI)
3. **선택**: 희망 시간 (드롭다운)
4. **입력**: 면접 시간 (예: 60분)

#### 5-3. 요청 전송
1. **클릭**: "요청 보내기" 버튼
2. **확인**: 성공 메시지 표시 ("면접 요청이 전송되었습니다.")
3. **자동**: 요청 목록 페이지로 이동

#### 5-4. 요청 상태 확인
1. **화면**: "내 면접 요청" 페이지
2. **확인**: 요청 내역에 "대기 중" 상태 표시

### 단계 (면접관)

#### 5-5. 면접관 계정으로 로그인
1. **준비**: 새 시크릿 모드 창 또는 다른 브라우저 열기
2. **접속**: `https://chub.ai.kr` 로그인
3. **로그인**: 카카오 계정 B (면접관용)으로 로그인

#### 5-6. 면접 요청 확인
1. **클릭**: 네비게이션 바에서 "알림" 또는 "면접 요청" 클릭
2. **화면**: 받은 면접 요청 목록 표시
3. **확인**: 피면접자가 보낸 요청 확인

#### 5-7. 요청 상세 조회
1. **클릭**: 면접 요청 카드 클릭
2. **화면**: 요청 상세 정보 표시
   - 요청자 정보
   - 요청 메시지
   - 희망 날짜 및 시간

#### 5-8. 요청 승인
1. **클릭**: "승인" 버튼
2. **확인**: 확인 모달 표시 ("면접 요청을 승인하시겠습니까?")
3. **클릭**: "확인" 버튼
4. **확인**: 성공 메시지 표시 ("면접이 승인되었습니다.")

#### 5-9. 승인 상태 확인
1. **확인**: 요청 상태가 "승인됨"으로 변경
2. **확인**: 피면접자 화면에서도 상태 변경 확인

**예상 결과:**
- 면접 요청이 데이터베이스에 저장됨 (interview_requests 테이블)
- 상태가 "PENDING" → "APPROVED"로 변경됨

## 시나리오 6: 실시간 채팅

### 목표
면접관과 피면접자 간 실시간 채팅 기능 시연

### 단계 (피면접자)

#### 6-1. 채팅 페이지 이동
1. **클릭**: 네비게이션 바에서 "메시지" 또는 "채팅" 클릭
2. **화면**: 채팅방 목록 표시

#### 6-2. 채팅방 선택
1. **클릭**: 면접관과의 채팅방 선택
2. **화면**: 채팅 메시지 창 표시

#### 6-3. 메시지 전송
1. **입력**: 메시지 입력창에 "안녕하세요, 면접 일정 조율 가능할까요?" 입력
2. **클릭**: "전송" 버튼 또는 Enter 키
3. **확인**: 메시지가 채팅창에 표시됨

### 단계 (면접관)

#### 6-4. 실시간 메시지 수신
1. **위치**: 면접관 계정 화면 (브라우저 2)
2. **자동**: 새 메시지 알림 표시 (빨간 뱃지)
3. **클릭**: 채팅 메뉴 클릭
4. **확인**: 피면접자가 보낸 메시지 실시간 표시

#### 6-5. 답장 전송
1. **입력**: "네, 다음 주 화요일 오후 2시는 어떠신가요?" 입력
2. **클릭**: "전송" 버튼
3. **확인**: 메시지 전송 및 표시

### 단계 (피면접자)

#### 6-6. 실시간 답장 수신
1. **자동**: 면접관의 답장이 실시간으로 표시됨
2. **확인**: 메시지 시간 및 발신자 표시
3. **확인**: 읽음 처리 (읽지 않은 메시지 카운트 0으로 변경)

#### 6-7. WebSocket 연결 확인 (개발자 도구)
1. **열기**: 개발자 도구 > Network 탭
2. **필터**: WS (WebSocket) 선택
3. **확인**: `/ws` 엔드포인트 연결 확인
4. **확인**: STOMP 프레임 주고받기 확인

**예상 결과:**
- WebSocket (STOMP) 연결 확립
- 메시지가 MongoDB에 실시간 저장됨 (messages 컬렉션)
- 채팅방 메타데이터 업데이트됨 (chatrooms 컬렉션)
- 읽지 않은 메시지 카운트 정상 작동

## 시나리오 7: 화상 면접 (WebRTC)

### 목표
WebRTC 기반 화상 면접 기능 시연

### 단계 (피면접자)

#### 7-1. 면접 시작
1. **클릭**: "내 면접" 페이지에서 승인된 면접 클릭
2. **클릭**: "면접 시작" 버튼
3. **확인**: 카메라/마이크 권한 요청 모달 표시
4. **클릭**: "허용" 버튼

#### 7-2. 면접 대기실 입장
1. **화면**: 면접 대기실 (로비) 표시
2. **확인**: 자신의 비디오 미리보기 표시
3. **확인**: 카메라/마이크 ON/OFF 버튼 표시

#### 7-3. 면접관 입장 대기
1. **대기**: 면접관이 입장할 때까지 대기
2. **확인**: "면접관이 입장하면 자동으로 연결됩니다." 메시지

### 단계 (면접관)

#### 7-4. 면접관 입장
1. **위치**: 면접관 계정 화면 (브라우저 2)
2. **클릭**: "내 면접" 페이지에서 해당 면접 클릭
3. **클릭**: "면접 시작" 버튼
4. **클릭**: 카메라/마이크 권한 "허용"

### 단계 (양쪽)

#### 7-5. WebRTC 연결 확립
1. **자동**: ICE Candidate 교환
2. **자동**: TURN/STUN 서버를 통한 NAT 통과
3. **자동**: Peer-to-Peer 연결 확립
4. **확인**: 양쪽 화면에 상대방 비디오 표시

#### 7-6. 화상 면접 진행
1. **확인**: 면접관 화면 (큰 화면)
2. **확인**: 자신의 화면 (작은 화면, PIP)
3. **테스트**: 카메라 ON/OFF 버튼 클릭
4. **테스트**: 마이크 ON/OFF 버튼 클릭
5. **확인**: 음성 송수신 확인

#### 7-7. WebRTC 연결 상태 확인 (개발자 도구)
1. **열기**: 개발자 도구 > Console
2. **확인**: WebRTC 로그 확인
3. **입력**: `chrome://webrtc-internals` (Chrome) 또는 `about:webrtc` (Firefox) 접속
4. **확인**: RTCPeerConnection 상태 확인

**예상 결과:**
- WebRTC P2P 연결 성공
- TURN/STUN 서버를 통한 NAT 통과
- 실시간 비디오/오디오 스트리밍

### 목표

4. **클릭**: "질문 시작" 버튼

### 단계 (피면접자)

#### 8-2. 답변 녹음 시작

#### 8-5. 변환된 텍스트 확인
1. **확인**: 답변이 텍스트로 표시됨
2. **확인**: 질문 목록에 답변 추가됨
3. **선택**: 필요 시 텍스트 수정 가능

### 단계 (면접관)

#### 8-6. GPT 기반 꼬리 질문 생성 (선택사항)
1. **클릭**: "꼬리 질문 생성" 버튼
2. **자동**: GMS GPT API로 꼬리 질문 요청
3. **대기**: AI 질문 생성 중 표시
4. **확인**: 생성된 꼬리 질문 표시
   - 예시: "내장 서버를 사용하면 어떤 장점이 있나요?"
5. **선택**: 질문 사용 또는 수정

**예상 결과:**
- 음성이 텍스트로 변환됨 (GMS Whisper API)

## 문제 발생 시 대응

### WebRTC 연결 실패
- TURN/STUN 서버 상태 확인: `turnserver.conf` 설정 검증
- 방화벽 포트 개방 확인
- `chrome://webrtc-internals` 에서 연결 상태 확인

### 채팅 메시지 전송 실패
- WebSocket 연결 확인: 개발자 도구 > Network > WS
- MongoDB 연결 상태 확인
- 백엔드 로그에서 STOMP 에러 확인

### 파일 업로드 실패
- 파일 크기 확인 (10MB 이하)
- 파일 형식 확인 (PDF만 허용)
- NGINX 설정 확인 (`client_max_body_size`)
- Docker Volume 마운트 확인

### STT 변환 실패
- GMS API Key 유효성 확인
- GMS 서버 상태 확인 (https://gms.ssafy.io/)
- 음성 파일 형식 확인 (MP3, WAV 등)

```sql
-- PostgreSQL 테스트 데이터 삭제
DELETE FROM questions WHERE interview_id IN (SELECT interview_id FROM interviews WHERE title LIKE '%Test%');
DELETE FROM interviews WHERE title LIKE '%Test%';
DELETE FROM interview_requests WHERE request_message LIKE '%테스트%';
DELETE FROM resumes WHERE pdf_url LIKE '%test%';
DELETE FROM interviewer_profiles WHERE introduction LIKE '%테스트%';
DELETE FROM users WHERE username LIKE '%테스트%';
```

```javascript
// MongoDB 테스트 데이터 삭제
use chub;
db.messages.deleteMany({ content: /테스트/ });
db.chatrooms.deleteMany({ lastMessage: /테스트/ });
```
