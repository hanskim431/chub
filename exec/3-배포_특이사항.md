# 3. 배포 특이사항

## 3.1 중요 주의사항

### 3.1.1 Hibernate DDL Auto 설정 주의

**현재 설정 (application.yml):**
```yaml
spring:
  jpa:
    hibernate:
      ddl-auto: create  # 매번 스키마 재생성!
```

**문제점:**
- `ddl-auto: create`는 애플리케이션 시작 시마다 **모든 테이블을 삭제하고 재생성**
- 기존 데이터가 모두 손실됨
- 개발 환경에서만 사용해야 함

**프로덕션 권장 설정:**
```yaml
spring:
  jpa:
    hibernate:
      ddl-auto: ${DDL_AUTO:update}  # 또는 validate
```

**DDL Auto 옵션:**
- `create`: 매번 테이블 삭제 후 재생성 (개발 전용)
- `create-drop`: 종료 시 테이블 삭제 (테스트 전용)
- `update`: 엔티티 변경 시 스키마 자동 업데이트 (주의 필요)
- `validate`: 엔티티와 스키마 일치 여부만 검증 (안전)
- `none`: 아무것도 하지 않음 (운영 권장)

**배포 전 체크리스트:**
- [ ] `DDL_AUTO` 환경변수를 `update` 또는 `validate`로 설정
- [ ] 초기 배포 시 `create`로 스키마 생성 후 `update`로 변경
- [ ] 중요 데이터가 있는 경우 반드시 백업 수행

## 3.2 Docker 멀티스테이지 빌드

### 3.2.1 Dockerfile 구조

**파일 위치:** `backend/chub/Dockerfile`

```dockerfile
# Stage 1: 빌드 스테이지
FROM gradle:8.12-jdk21 AS builder
WORKDIR /app
COPY . .
RUN gradle build -x test --no-daemon

# Stage 2: 실행 스테이지
FROM eclipse-temurin:21-jre-alpine
WORKDIR /app
COPY --from=builder /app/build/libs/*.jar app.jar
EXPOSE 8080
ENTRYPOINT ["java", "-jar", "-Dspring.profiles.active=prod", "app.jar"]
```

### 3.2.2 빌드 특이사항

**빌드 플래그:**
- `-x test`: 테스트 제외 (빌드 시간 단축)
- `--no-daemon`: Gradle 데몬 비활성화 (Docker 빌드 최적화)

**이미지 크기 최적화:**
- Builder 이미지: `gradle:8.12-jdk21` (빌드 도구 포함)
- Runtime 이미지: `eclipse-temurin:21-jre-alpine` (경량 JRE만)
- 최종 이미지 크기: 약 300MB (JDK 포함 시 600MB+)

**프로파일 강제 설정:**
- `-Dspring.profiles.active=prod`: 항상 프로덕션 프로파일 사용
- 환경변수 `SPRING_PROFILES_ACTIVE`로 오버라이드 가능

## 3.3 NGINX 설정 특이사항

### 3.3.1 파일 업로드 크기 제한

```nginx
server {
    client_max_body_size 10M;  # 최대 10MB
}
```

**이유:**
- Resume PDF 파일 업로드 제한
- 너무 큰 파일로 인한 서버 부하 방지

**변경 방법:**
- `nginx.conf` 수정 후 `nginx -t`로 검증
- `systemctl reload nginx`로 재시작

### 3.3.2 WebSocket 프록시 설정

```nginx
location /ws/ {
    proxy_pass http://127.0.0.1:8080;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_read_timeout 86400s;  # 24시간
    proxy_send_timeout 86400s;
}
```

**특이사항:**
- `proxy_read_timeout`: 24시간으로 설정 (장시간 연결 유지)
- WebSocket 연결이 끊기지 않도록 긴 타임아웃 필요
- STOMP over WebSocket 사용으로 인한 설정

### 3.3.3 파일 서빙 설정

```nginx
location /files/resumes {
    alias /app/uploads/resumes;
    expires 1y;
    add_header Cache-Control "public, immutable";
    add_header Access-Control-Allow-Origin "https://chub.ai.kr" always;
    autoindex off;
    try_files $uri =404;
}
```

**특이사항:**
- `alias` vs `root`: `alias`는 경로 완전 치환
- `expires 1y`: 1년 캐싱 (파일은 변경되지 않는다고 가정)
- `autoindex off`: 디렉토리 리스팅 비활성화 (보안)
- CORS 헤더 추가: 프론트엔드에서 파일 접근 허용

### 3.3.4 Docker Volume 마운트 필수

**docker-compose.yml:**
```yaml
services:
  backend:
    volumes:
      - resume_uploads:/app/uploads/resumes

volumes:
  resume_uploads:
```

**NGINX 컨테이너 또는 호스트:**
```bash
# NGINX가 호스트에서 실행되는 경우
docker run -v resume_uploads:/app/uploads/resumes ...

# 또는 호스트 경로 직접 마운트
-v /var/chub/uploads:/app/uploads/resumes
```

**주의사항:**
- NGINX가 `/app/uploads/resumes` 경로에 읽기 권한이 있어야 함
- 백엔드와 NGINX가 같은 볼륨을 공유해야 함
- 파일이 DB가 아닌 로컬 스토리지에 저장됨

## 3.4 Jenkins CI/CD 파이프라인

### 3.4.1 파이프라인 구조

**Jenkinsfile 주요 스테이지:**

1. **Change Detection**: Git diff로 변경 파일 감지
2. **Frontend Build**: `npm install` → `npm run build`
3. **Backend Build**: Docker 이미지 빌드
4. **Frontend Deploy**: `rsync`로 정적 파일 배포
5. **Backend Deploy**: `docker-compose up -d`
6. **Health Check**: API 응답 확인

### 3.4.2 배포 특이사항

#### Frontend 배포

```groovy
stage('Frontend Deploy') {
    steps {
        sh '''
            # 기존 파일 백업
            if [ -d /var/www/html ]; then
                mv /var/www/html /var/www/html.backup.$(date +%Y%m%d_%H%M%S)
            fi

            # 새 파일 배포
            mkdir -p /var/www/html
            rsync -av --delete frontend/chub/dist/ /var/www/html/

            # 권한 설정
            chmod -R 755 /var/www/html
        '''
    }
}
```

**특이사항:**
- 배포 전 자동 백업 (롤백 가능)
- `rsync --delete`: 이전 파일 완전 삭제
- 권한 755: NGINX 읽기 권한 보장

#### Backend 배포

```groovy
stage('Backend Deploy') {
    steps {
        sh '''
            cd backend

            # 기존 컨테이너 중지
            docker-compose down || true

            # 새 컨테이너 시작
            docker-compose up -d --build

            # 시작 대기
            sleep 10

            # 로그 확인
            docker-compose logs --tail=50 backend
        '''
    }
}
```

**특이사항:**
- `|| true`: 실패해도 계속 진행 (첫 배포 시 컨테이너 없음)
- `--build`: 이미지 강제 재빌드
- `sleep 10`: 컨테이너 완전 시작 대기

### 3.4.3 환경변수 주입

**Jenkinsfile:**
```groovy
environment {
    DB_USERNAME = credentials('db-username')
    DB_PASSWORD = credentials('db-password')
    JWT_SECRET_KEY = credentials('jwt-secret-key')
    // ... 기타 시크릿
}

stage('Frontend Build') {
    steps {
        sh '''
            cd frontend/chub

            # .env 파일 생성
            cat > .env << EOF
VITE_API_URL=https://chub.ai.kr
VITE_API_MOCK=false
VITE_STUN_SERVER=stun:chub.ai.kr:3478
VITE_TURN_SERVER=turn:chub.ai.kr:3478
VITE_TURN_USERNAME=chubuser
VITE_TURN_PASSWORD=chubpassword123
EOF

            npm install
            npm run build
        '''
    }
}
```

**주의사항:**
- Jenkins Credentials에 모든 시크릿 등록 필요
- `.env` 파일은 빌드 시마다 동적 생성
- 시크릿이 빌드 로그에 노출되지 않도록 주의

## 3.5 SSL/TLS 인증서 설정

### 3.5.1 Let's Encrypt 인증서

**nginx.conf:**
```nginx
server {
    listen 443 ssl;
    server_name chub.ai.kr;

    ssl_certificate /etc/letsencrypt/live/chub.ai.kr/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/chub.ai.kr/privkey.pem;
}
```

### 3.5.2 인증서 발급 (Certbot)

```bash
# Certbot 설치
sudo apt-get install certbot python3-certbot-nginx

# 인증서 발급
sudo certbot --nginx -d chub.ai.kr

# 자동 갱신 테스트
sudo certbot renew --dry-run
```

### 3.5.3 Coturn SSL 설정

**turnserver.conf:**
```conf
cert=/etc/letsencrypt/live/chub.ai.kr/fullchain.pem
pkey=/etc/letsencrypt/live/chub.ai.kr/privkey.pem
```

**주의사항:**
- Coturn도 같은 인증서 사용
- 인증서 갱신 시 Coturn 재시작 필요
- `systemctl restart coturn`

## 3.9 성능 최적화

### 3.9.1 JPA 배치 처리

**application-prod.yml:**
```yaml
spring:
  jpa:
    properties:
      hibernate:
        jdbc:
          batch_size: 100          # 배치 INSERT 크기
        order_inserts: true        # INSERT 순서 최적화
        order_updates: true
```

### 3.9.2 Connection Pool 튜닝

```yaml
spring:
  datasource:
    hikari:
      maximum-pool-size: 10      # 프로덕션: 10
      minimum-idle: 2
      connection-timeout: 20000
      idle-timeout: 300000
      max-lifetime: 1200000
```

**튜닝 가이드:**
- `maximum-pool-size`: CPU 코어 수 × 2 + 디스크 수
- 트래픽이 많으면 증가, 서버 리소스 고려

### 3.9.3 NGINX 캐싱

```nginx
location / {
    # 정적 파일 캐싱
    location ~* \.(js|css|png|jpg|jpeg|gif|ico|svg|woff|woff2)$ {
        expires 1y;
        add_header Cache-Control "public, immutable";
    }
}
```

**FileStorageService.java:**

if (!file.getContentType().equals("application/pdf")) {
    throw new InvalidFileTypeException("Only PDF files are allowed");

### 3.10.3 SQL Injection 방지

**JPA를 사용하여 자동 방지:**
```java
// 안전: JPA 쿼리

// 위험: Native Query (사용 시 주의)
@Query(value = "SELECT * FROM users WHERE sub = ?1", nativeQuery = true)
User findBySubNative(String sub);
```
